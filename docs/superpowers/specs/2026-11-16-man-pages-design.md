# Man pages for irsync and fileset

Issue: https://github.com/irsync-dev/irsync/issues/51

## Intent

`man irsync` and `man fileset` find nothing after an install. The only
reference is the website. That is a poor fit for a tool that runs on servers
and over bad links, and the online book describes the newest release, not the
one installed.

Build `irsync(1)` and `fileset(1)` from the book's Markdown and ship them with
the binaries, so the pages are available offline and always match the
installed version.

## Goals

- `man irsync` and `man fileset` work after a default install on Linux and
  macOS, through the install script, Homebrew, apt and dnf.
- The book's Markdown is the single source. The pages cannot drift from it.
- The installed pages name the installed version.
- CI fails when the conversion fails or the pages render with warnings.
- The install script can remove what it installed (`--uninstall`).

## Non-goals

- Man pages for `cargo install`. It can only install binaries. A TODO entry
  records the follow-up: cargo-binstall packaging.
- A page for the configuration file (`irsync.toml(5)`) or for the
  contributor tools (`filegen`, `irsync-stress`, `irsync-netstress`).
- An uninstall for Homebrew, apt or dnf. Their package managers do that.
- Changing `site/install.sh`.

## Anti-goals

- Hand-written or committed roff that can go stale against the book.
- Editing `.github/workflows/release.yml` by hand. It is generated by
  `dist generate`.
- A second network download in the install script just for the pages.
- An installer on a release that needs a matching version of
  `site/install.sh`. The script on the homepage must keep working with every
  release, old and new.

## Constraints found in the project

- dist 0.34.0 generates `release.yml`, the shell installer and the Homebrew
  formula. Its shell installer moves only the binaries out of the tarball.
  Its formula installs leftover tarball files into `pkgshare`
  (`share/irsync/`), which `man` does not search. Neither has a hook.
- dist's custom local publish jobs are broken in 0.34.0 (see the comment in
  `dist-workspace.toml`). dist's `extra-artifacts` setting does work: it runs
  a build command in the `build-global-artifacts` job and attaches the named
  files to the release. That job runs on Ubuntu after the per-target builds
  and has every tarball and its `.sha256` file in `target/distrib/`.
- A release is immutable once published. Every file must be attached by
  `release.yml` itself.
- `site/install.sh` picks a release tag, downloads
  `irsync-installer.sh` from that release, and runs it with the remaining
  arguments. That contract stays.
- The deb and rpm packages are built from the released Linux tarballs
  (`packaging/build-packages.sh`, `packaging/nfpm.yaml`).
- `man` on Linux (man-db) and on macOS derives a search path from `PATH`: for
  `X/bin` it looks in `X/share/man`. So pages in `~/.local/share/man/man1`
  are found when `~/.local/bin` is on `PATH`, with no `MANPATH` setup.
- No book chapter uses `{{#include}}` today.
- A trial `pandoc -s -f gfm -t man` of `reference/command-line.md` renders
  correctly, tables included. `mandoc -T lint` reports only the missing date
  and a few skipped paragraph macros.

## Approaches

**Building the pages.** One way was considered seriously: pandoc at build
time from the book's Markdown, as the issue proposes. Committing generated
roff was rejected because it can go stale. Embedding the pages in the
binaries was rejected because it puts roff files into the cargo build.

**Getting the pages through the install script.** Three ways:

1. *Our own installer.* Stop using dist's shell installer. Install the
   binaries and the pages from one download of the tarball. Costs a shell
   script we own and test; gains one download, no reliance on dist internals,
   and a place for `--uninstall`.
2. *Wrap dist's installer.* Download the tarball, point dist's installer at
   it with `IRSYNC_DOWNLOAD_URL=file://…`, then copy the pages out. Keeps
   dist's `PATH` and receipt logic. Relies on an override meant for mirrors,
   fails with wget, and still duplicates the platform detection.
3. *Pages embedded in the binary*, written out after install. Rejected, as
   above.

**Chosen: 1, in this form (decided by Mike):** `site/install.sh` does not
change. The second stage, `irsync-installer.sh`, is generated by us instead
of by dist and attached to each release under the same name. The homepage
script therefore stays compatible with any release version.

**Homebrew.** One sensible way: add a `man1.install` line to dist's formula
before it is pushed to the tap. Replacing dist's formula with our own
template was rejected as more to maintain for the same result.

## Design

### The pages

| Page | Built from |
| --- | --- |
| `irsync.1` | `book/src/reference/command-line.md`, then `book/src/reference/management.md` |
| `fileset.1` | `book/src/fileset/reference.md` |

`tools/build-man.sh OUTDIR` builds both pages into `OUTDIR/man1/`. For each
page it:

1. Reads a small per-page header kept next to the script's inputs (for
   example `packaging/man/irsync.md`, `packaging/man/fileset.md`). The header
   holds the man-only framing: the NAME line and the SEE ALSO section. The
   SYNOPSIS, EXIT STATUS, ENVIRONMENT and FILES content already exists in the
   chapters (`Command line`'s opening block, `Exit codes`, `Environment`,
   fileset's `Commands`, `Files`, `Exit codes`) and comes from there.
2. Concatenates the header and the chapters, in the order above, and runs
   pandoc from GitHub-flavoured Markdown to man format with a Lua filter.
3. Sets the title block from pandoc variables: name, section 1, the version
   from `packaging/dist/dist.toml` (footer `irsync X.Y.Z`), and the date of
   the commit being built (`git log -1 --format=%cs`), so two builds of one
   commit give the same page.

The Lua filter:

- Shifts headings. For a page's first chapter (`command-line.md`,
  `fileset/reference.md`) the title is dropped, `##` becomes a top-level man
  section (`.SH`, upper case) and `###` becomes `.SS`.
- Treats `management.md` differently (my call): its title becomes one
  section, `MANAGEMENT COMMANDS`, holding its intro paragraphs, and its `##`
  headings (`host`, `export`, `grant`, ...) become subsections of it. The
  filter then moves `ENVIRONMENT` and `EXIT STATUS` (the chapters' `Exit
  codes`) to the end of the page, before SEE ALSO, where man readers expect
  them. The book keeps its chapter order.
- Rewrites links. A link to an anchor in the same page keeps its text only. A
  link to another chapter keeps its text and is followed by the chapter's
  full URL under `https://irsync.org/book/`, so the pointer still leads
  somewhere. An absolute URL is left as pandoc renders it.
- Fails the build on an `{{#include}}` or other `{{#…}}` directive, with a
  message saying the filter must learn to expand it. None exist today; this
  keeps a future one from shipping as literal text.

fileset's chapter opens with a paragraph about where the crate lives and a
`cargo install` block. Those lines are wrong in a man page. Move them out of
the reference chapter (the fileset introduction already covers installing)
instead of teaching the filter to cut them.

SEE ALSO in each page names the other page and the book's URL.

### Tarball

`packaging/dist/build.sh` calls `tools/build-man.sh` and places the result
at `packaging/dist/man/man1/`. `packaging/dist/dist.toml` lists `man` under
`include`, so each tarball holds `man/man1/irsync.1` and
`man/man1/fileset.1` next to the binaries.

pandoc is added to the release runners through `dist-workspace.toml`
(`[dist.dependencies.apt]` and `[dist.dependencies.homebrew]`), then
`dist generate` regenerates `release.yml`.

### The installer

`packaging/installer/irsync-installer.sh.in` is a POSIX `sh` template.
`packaging/installer/build-installer.sh` fills in the version, the release
download URL and the three tarballs' SHA-256 checksums (read from
`target/distrib/*.sha256`) and writes `irsync-installer.sh`. dist runs it as
an `extra-artifacts` build and attaches the result. `shell` is removed from
dist's `installers`; `homebrew` stays.

Facts about that job, checked in dist 0.34.0's source:

- dist ignores a non-zero exit from an extra-artifacts build. It fails only
  when the output file is missing. So `build-installer.sh` must write
  `irsync-installer.sh` as its last step and leave no file behind on error.
- The job installs none of `[dist.dependencies]`. The generator may use only
  what a plain Ubuntu 22.04 runner has. It does not need pandoc.
- The existing attestation step covers the file, like every other artifact.

The generated script, in order:

1. Parses arguments: `--uninstall`, `--help`. Anything else is an error.
2. Detects the platform and picks one of the three tarballs:
   `aarch64-apple-darwin`, `aarch64-unknown-linux-musl`,
   `x86_64-unknown-linux-musl`. Anything else stops with a message that
   names the supported platforms and the releases page.
3. Downloads the tarball once, HTTPS only, with curl or wget under the same
   rules as `site/install.sh` (including the BusyBox wget refusal).
4. Verifies the SHA-256 against the embedded value, with `sha256sum` or
   `shasum -a 256`. A mismatch or a missing tool stops the install.
5. Unpacks to a temporary directory and installs:
   - `irsync`, `fileset` to `~/.local/bin`
   - `man/man1/*.1` to `~/.local/share/man/man1`

   Files are copied to a temporary name in the target directory and renamed
   into place, so a running `irsync` is replaced safely.
6. If `~/.local/bin` is not on `PATH`, prints the line to add for the user's
   shell. It does not edit shell startup files. (My call: dist's installer
   edited them unless `IRSYNC_NO_MODIFY_PATH=1`; printing is simpler and
   never surprises. The variable is accepted and ignored.)
7. Writes no receipt file. An old `~/.config/irsync/irsync-receipt.json`
   from dist's installer is left alone on install.

dist's installer, used by every release so far, also wrote
`~/.config/irsync/env.sh` and `env.fish`, a line sourcing `env.sh` in the
shell startup files (`.profile`, `.zshrc`, `.zshenv`, bash's files), and
`~/.config/fish/conf.d/irsync.env.fish`. The new installer leaves all of
these alone, on install and on uninstall (my call: we never edit startup
files, and only beta users have them). When `--uninstall` finds
`~/.config/irsync/env.sh`, it prints a note: the startup files still source
it, so remove those lines before deleting the config directory.
`book/src/how-to/clean-up.md` says the same.

As in `site/install.sh`, all work happens in a `main` function called on the
last line, so a download cut short runs nothing.

`--uninstall` removes `~/.local/bin/irsync`, `~/.local/bin/fileset`,
`~/.local/share/man/man1/irsync.1`, `~/.local/share/man/man1/fileset.1` and
an old receipt file if present. It downloads nothing. It leaves the config
and state directories alone and prints where they are (the book's
`Clean up state` page covers them). Missing files are not an error. Through
the homepage it is `curl … https://irsync.org/install.sh | sh -s -- --uninstall`.
A channel flag must still come first, and until v0.1.0 there is no stable
release, so the docs show `sh -s -- --beta --uninstall` until then.

### Homebrew

`publish-homebrew.yml` runs a small script on the downloaded formula before
committing it: it inserts `man1.install Dir["man/man1/*.1"]` ahead of the
line that computes `leftover_contents`, so the pages leave the directory
before the leftovers go to `pkgshare`. The script fails if the anchor line
is missing or appears more than once, so a dist upgrade that reshapes the
formula is caught instead of silently shipping no pages. The workflow
checks out only the tap today; it needs a second checkout of irsync at the
tag to get the script.

The tap's formula then differs by that line from the attested `irsync.rb`
on the release. Record this in `docs/SUPPLY_CHAIN_DECISIONS.md`.

### deb and rpm

`packaging/nfpm.yaml` gains two entries, `/usr/share/man/man1/irsync.1.gz`
and `/usr/share/man/man1/fileset.1.gz`, mode 0644.
`packaging/build-packages.sh` takes the pages from the released tarball and
gzips them (`gzip -9n`, so the result is reproducible).

### Checks

- `tools/ci.sh check` runs `tools/build-man.sh` and fails on any pandoc
  warning (`--fail-if-warnings`) and on any `mandoc -T lint` message at
  warning level or above. It runs for every code change on Linux and macOS.
  CI's "docs only" shortcut must not skip it when a source chapter, the
  headers or the script change: treat those paths as code in
  `.github/scripts/code-changed.sh`.
- `tools/dev-setup.sh` checks for pandoc and mandoc and says how to install
  them. CI installs them on its runners.
- Tests, in the style of the existing Python tests under `packaging/tests`
  and `site/tools`:
  - the installer generator: checksums and version land in the output;
  - the installer, run against a local fake release with `HOME` set to a
    temporary directory: install places four files, a bad checksum stops it,
    an unsupported platform stops it, `--uninstall` removes them and is safe
    to run twice;
  - the formula edit: the line is inserted once, and a formula without the
    anchor fails;
  - the packages: the `.deb` lists both man pages.
- `tools/ci.sh release-build` (Linux) checks that the built tarball holds
  both pages.
- `.github/scripts/tests/test_workflow_policy.py` mentions the installer
  only in a comment of the attestation test; update the comment.
- `code-changed.sh` covers pull requests only, and `ci.yml`'s push trigger
  ignores `book/**`. Leave the push trigger: `main` only takes pull requests.

### Docs

- `book/src/contributing/releasing.md`: the installer paragraph (no receipt,
  no `PATH` editing, the pages, `--uninstall`), and what the first release
  rehearsal should check (`man irsync` works).
- README and the book's install sections: drop the receipt note, add
  `--uninstall` and one line that `man irsync` and `man fileset` work.
- `book/src/how-to/clean-up.md`: mention `--uninstall`.
- `book/src/contributing/setup.md` and `AGENTS.md`: pandoc in the tool list.
- `TODO.md`: add cargo-binstall packaging, which would also bring man pages
  to cargo users.

## Left to the builder

- The exact names and layout of the header files, the filter and the
  installer template.
- How the installer detects the user's shell for the `PATH` hint.
- Whether the Lua filter or small edits to the chapters fix each lint
  warning, as long as the book still reads well.
- The pandoc version CI and the release runners use, as long as CI and the
  release build agree closely enough that a page that passes CI builds in a
  release.
