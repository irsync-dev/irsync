# Man Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `irsync(1)`, `fileset(1)` and `irsync.toml(5)` from the book's Markdown and ship them through the install script, Homebrew, apt and dnf.

**Architecture:** `tools/build-man.sh` runs pandoc with a Lua filter over the book's reference chapters plus a small header per page. `packaging/dist/build.sh` puts the pages into every release tarball. Our own generated `irsync-installer.sh` replaces dist's shell installer and installs binaries and pages from one tarball download. The deb, rpm and Homebrew paths take the pages from the same tarball.

**Tech Stack:** POSIX sh, bash, pandoc (Lua filter), mandoc, Python `unittest`, cargo-dist 0.34.0, nfpm, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-16-man-pages-design.md`. Read it first; this plan does not repeat its reasoning.

## Global Constraints

- The book's Markdown is the only source. No generated roff is committed.
- Never edit `.github/workflows/release.yml` by hand. Change `dist-workspace.toml`, run `dist generate`, commit the result.
- `site/install.sh` does not change.
- The installer on a release is named `irsync-installer.sh`, as today.
- Shell scripts the user runs (`irsync-installer.sh`) are POSIX `sh`: no bashisms, all work inside `main`, called on the last line.
- Downloads are HTTPS only, with the same curl and wget rules as `site/install.sh` (including the BusyBox wget refusal).
- Install paths: `~/.local/bin`, `~/.local/share/man/man1`, `~/.local/share/man/man5`. Package paths: `/usr/share/man/man1/*.1.gz`, `/usr/share/man/man5/*.5.gz`, mode 0644.
- Tarball layout: `man/man1/irsync.1`, `man/man1/fileset.1`, `man/man5/irsync.toml.5`.
- Release targets: `aarch64-apple-darwin`, `aarch64-unknown-linux-musl`, `x86_64-unknown-linux-musl`. Tarballs are `irsync-<target>.tar.xz` with one top-level directory `irsync-<target>/`.
- The installer never edits shell startup files and writes no receipt.
- Commit messages: a short summary line, a blank line, a brief plain-English why. No attribution trailers of any kind.
- Work on a feature branch off `man-pages-design` (the spec lives there); `main` takes pull requests only. Before the pull request, run `tools/ci.sh` (all jobs; `release-build` on Linux).
- Python tests follow the repo's style: `unittest`, `subprocess`, temporary directories, no new dependencies.

## Review Focus

1. **Option names must survive conversion.** `--dry-run` in prose or a table must not become an en dash plus `dry-run`. A reader copies flags from the page. Pinned in Task 1.
2. **A failed install leaves the old install untouched.** A bad checksum or a failed download must not remove or half-replace existing binaries and pages. Pinned in Task 4.
3. **A home directory with a space in its name.** Install and uninstall must work with `HOME="/tmp/x y"`. Pinned in Task 4.
4. **Upgrading over dist's old install.** Existing binaries, an old receipt and `env.sh` are present; install succeeds and leaves the receipt and `env.sh` alone. Pinned in Task 4.
5. **A truncated installer download runs nothing.** Cutting the script at any line must install nothing. Pinned in Task 4.

- [ ] **Step 4: Write `packaging/man/filter.lua` and `tools/build-man.sh`.**

The script, per page: check every input for `{{#` and fail naming the file; concatenate header-top, chapters, header-bottom, with a marker comment `<!-- chapter: PATH -->` before each chapter so the filter knows which chapter a block came from; run

```sh
pandoc --from gfm --to man --standalone --fail-if-warnings \
  --lua-filter packaging/man/filter.lua \
  -V title=NAME -V section=N -V footer="irsync $version" -V date="$date" \
  -V header="irsync manual"
```

(`gfm` has no `smart` extension, which is what keeps `--` literal.) Then strip the paragraph macros mandoc warns about (`.PP` directly after `.SH` or `.SS`) and write the page.

The filter's rules, all from the spec:
- First chapter of a page: drop the `#` title; the text before the first `##` goes under a `SYNOPSIS` section when it is the leading code block (`command-line.md`, and fileset's `Commands` block stays where it is) and under `DESCRIPTION` otherwise; `##` becomes level 1, `###` level 2.
- `management.md`: its `#` title becomes the level 1 section `MANAGEMENT COMMANDS`; its `##` become level 2, `###` level 3.
- Rename `Exit codes` to `EXIT STATUS`. In `irsync.1`, move the `ENVIRONMENT` and `EXIT STATUS` sections to just before `SEE ALSO`.
- Links: same-page anchor (`#x`) keeps its text only. A link into `reference/configuration.md` from `irsync.1` becomes its text followed by ` (see irsync.toml(5))`; a link into `command-line.md` or `management.md` from `irsync.toml.5` becomes its text followed by ` (see irsync(1))`; a link between the two `irsync.1` chapters keeps its text only. Any other relative `.md` link becomes its text followed by ` (https://irsync.org/book/<path>.html#<anchor>)`, the path resolved against the chapter's directory under `book/src`. Absolute URLs are untouched.

Target pandoc 3.1 or newer (Ubuntu 24.04 ships 3.1.3; the local one is 3.1.11).

**Interfaces:**
- Produces: `packaging/installer/build-installer.sh DISTRIB_DIR OUT_FILE`. It reads the version from `packaging/dist/dist.toml` and, for each of the three targets, the first field of `DISTRIB_DIR/irsync-<target>.tar.xz.sha256`. It fills the template's placeholders `@VERSION@`, `@BASE_URL@` (`https://github.com/irsync-dev/irsync/releases/download/v<version>`), `@SHA256_AARCH64_APPLE_DARWIN@`, `@SHA256_AARCH64_UNKNOWN_LINUX_MUSL@`, `@SHA256_X86_64_UNKNOWN_LINUX_MUSL@`. It writes to a temporary file and renames it to `OUT_FILE` as the last step. On any error (a missing or malformed checksum file, a placeholder left unfilled) it exits non-zero **and leaves no `OUT_FILE`**: dist ignores the exit status of this build and fails only when the file is missing.
- Produces: the generated script. Arguments: none (install), `--uninstall`, `--help`; anything else exits 2 with a usage line. Test-only environment, documented in the script's header the way `site/install.sh` documents its own: `IRSYNC_INSTALLER_ARCHIVE_DIR=DIR` reads `DIR/irsync-<target>.tar.xz` instead of downloading.
- Messages go to stderr with the prefix `irsync: `, as in `site/install.sh`.

Behaviour (spec, "The installer"): detect platform from `uname -s` and `uname -m` (`Darwin`+`arm64` → `aarch64-apple-darwin`; `Linux`+`aarch64`|`arm64` → `aarch64-unknown-linux-musl`; `Linux`+`x86_64`|`amd64` → `x86_64-unknown-linux-musl`; else stop, naming the three supported platforms and `https://github.com/irsync-dev/irsync/releases`). Download once to a temp dir, verify SHA-256 with `sha256sum` or `shasum -a 256` (neither present: stop), unpack with `tar -xJf` (stop with a clear message if tar cannot read xz), then install each file by copying to a temporary name in the target directory and renaming. Binaries get mode 0755, pages 0644. Only after verification succeeds is anything under `$HOME` touched. If `~/.local/bin` is not on `PATH`, print the line to add; `IRSYNC_NO_MODIFY_PATH` is accepted and ignored. End with `installed irsync <version>` and a line that `man irsync` works.

`--uninstall` removes exactly: `~/.local/bin/irsync`, `~/.local/bin/fileset`, `~/.local/share/man/man1/irsync.1`, `~/.local/share/man/man1/fileset.1`, `~/.local/share/man/man5/irsync.toml.5`, `~/.config/irsync/irsync-receipt.json`. No download, no platform check. It does not remove directories. It prints that config and state were left in place and points to `https://irsync.org/book/how-to/clean-up.html`. If `~/.config/irsync/env.sh` exists it also prints that shell startup files still source it and those lines must be removed before deleting `~/.config/irsync`.
