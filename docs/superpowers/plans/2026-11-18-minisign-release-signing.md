# Minisign Release Signing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every release file carries a minisign signature made with an offline key, and irsync, `install.sh` and users can check it.

**Architecture:** `release.yml` publishes a draft instead of a release. A maintainer runs `.github/scripts/sign-release.sh` locally: it checks the draft's files, signs them all with one `minisign` call, uploads the `.minisig` files, publishes the draft and starts `release-resume.yml`. irsync gets a `signature` module (crate `minisign-verify`) with the public keys built in, used by a hidden `verify-signature` command and by SSH onboarding's release download. `site/install.sh` checks the installer's signature before running it.

**Tech Stack:** Rust (`minisign-verify` 0.3), bash, POSIX sh, Python `unittest`, GitHub Actions, `gh`, minisign.

**Spec:** GitHub issue #89 (`gh issue view 89`), including its two test comments.

## Global Constraints

- Public keys live in one file: `packaging/signing/release-keys.pub`. Format: one or more standard minisign public key files concatenated (an `untrusted comment:` line, then a base64 key line). Every consumer reads keys from it or is tested against it.
- Each release file `F` gets `F.minisig` next to it on the release. Every file is signed, including the `.sha256` files.
- The trusted comment of every signature is exactly `irsync vX.Y.Z` (the tag). Verifiers that know the tag require an exact match; this blocks swapping in an older release's signed files.
- Only prehashed signatures (minisign's default since 0.10) are accepted; `allow_legacy = false`.
- The hidden command is `irsync verify-signature`. Exit 0 = good, 1 = bad, missing or untrusted signature, 2 = usage error.
- `release.yml` is changed only through `.github/scripts/release-yml.sh`; never by hand.
- Merge order: PR A (Tasks 1–5) before PR B (Tasks 6–8). PR C (Task 9) only after the first signed release is published. A release cut with PR B but without PR A would break SSH onboarding to other platforms.
- Commit messages: a summary line, a blank line, a short why. No attribution trailers.
- Before each push: `tools/ci.sh check`; for Tasks 2–4 also `tools/ci.sh workflows`, and for Task 2 `tools/ci.sh release-build`.

## Review Focus

1. **An older release's signed files served for a newer tag** (downgrade): must fail on the trusted comment. Tests in Task 6 (`rejects_wrong_trusted_comment`) and Task 8 (`fetch_rejects_sums_signed_for_other_tag`).
2. **A release with no `.minisig`** where one is expected: a hard error in `release::fetch` and in `install.sh` when a verifier exists, never a silent pass. Tests in Task 8 (`fetch_fails_without_signature`) and Task 9 (`test_missing_signature_fails`).
3. **Key rotation:** a signature by the second key in `release-keys.pub` passes; a key not in the file fails. Task 6 (`accepts_second_key`, `rejects_unknown_key`).
4. **An interrupted signing run:** the draft already has some `.minisig` files. The script replaces them and refuses to publish while any file lacks one. Task 4 (`test_replaces_stale_signatures`, `test_refuses_publish_when_a_signature_is_missing`).
5. **An old irsync on `PATH` without the command:** `install.sh` must notice, run nothing else through it, and fall through to `minisign` or the warning. Task 9 (`test_old_irsync_on_path_falls_through`).

### Task 4: The signing script

**Files:**

**Interfaces:**
- Consumes: the draft from Task 2, `release-keys.pub`.
- Produces: `sign-release.sh [--key PATH] [--no-publish] VERSION`. `--key` defaults to minisign's default (`~/.minisign/minisign.key`). `IRSYNC_SIGN_KEYS_FILE` overrides `packaging/signing/release-keys.pub` (tests only).

Steps the script runs, in order, stopping with a clear error at the first failure:
1. Needs `gh`, `minisign`, `sha256sum` or `shasum`. Version must pass `check-release-tag.sh`.
2. `gh release view vX.Y.Z --json isDraft,assets,targetCommitish`: must exist and be a draft.
3. Download every asset to a temp dir. The non-`.minisig` files must be exactly: `irsync-<t>.tar.xz` and `.sha256` for the three targets in `dist-workspace.toml`, `source.tar.gz` and `.sha256`, `irsync-installer.sh`, `irsync.rb`, `sha256.sum`, `dist-manifest.json`. Anything missing or extra → refuse.
4. Every file in `sha256.sum` and every `.sha256` matches.
5. `gh attestation verify <f> --repo irsync-dev/irsync --signer-workflow irsync-dev/irsync/.github/workflows/release.yml` for each file.
6. Print version, commit and file list; ask `Sign these files? [y/N]`.
7. One call: `minisign -S -s KEY -t "irsync vX.Y.Z" -m <all files>`.
8. Verify each new `.minisig` against `release-keys.pub` with the expected trusted comment (catches signing with the wrong key).
9. `gh release upload vX.Y.Z --clobber <all .minisig>`; re-read the asset list and check every file has its `.minisig`.
10. Unless `--no-publish`: check again that the tag `vX.Y.Z` does not exist (`git/matching-refs/tags/`, as `release-start-check.sh` does); a tag pushed by hand while the draft waited would otherwise take the release. Publish with `gh api -X PATCH repos/irsync-dev/irsync/releases/<id> -F draft=false -f make_latest=legacy`: `gh release edit --draft=false` would mark every published release Latest, including a patch on an older line, while today's `gh release create` lets GitHub decide by date and version. Check `isDraft` false and `immutable` true, then `gh workflow run release-resume.yml --ref vX.Y.Z -f tag=vX.Y.Z`.
