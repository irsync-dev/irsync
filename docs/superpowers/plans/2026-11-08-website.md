# irsync Website and Book Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static site for irsync: a landing page at `/` and an mdbook at `/book/` organised by Diátaxis, styled from the irsync design system, holding all user and contributor documentation (moved, not copied), deployed to Cloudflare Pages with `dev.irsync.org` as staging and `irsync.org` as production.

**Architecture:** `site/` holds the landing page, the vendored design tokens, the build, check and deploy scripts; `book/` holds the mdbook. `site/build.sh` generates CSS custom properties from `site/tokens.json`, builds the book and assembles `target/site/` (landing at the root, book under `book/`). `site/tools/check.py` guards the result: every internal link and anchor resolves, no moved file survives or is still referenced, and every irsync flag the docs show exists in `irsync --help`. Content moves into the book part by part, each move deleting the original and fixing its inbound links. Deploys go through `wrangler`: by hand until the repository is on GitHub, then a workflow deploys `main` to staging and a manual workflow promotes staging's exact build output to production.

**Tech Stack:** mdbook 0.5.2; Python 3 standard library only (generator, checker, their `unittest` tests); plain HTML and CSS for the landing page (no JavaScript framework, no build tool); `wrangler` via `npx`, pinned; GitHub Actions; Cloudflare Pages `_headers`.

**Spec:** `docs/superpowers/specs/2026-11-08-website-design.md`

## Global Constraints

- All content comes from this repository. When in doubt, the code is the source of truth, then the documentation in the repository.
- The design system (https://claude.ai/artifact/GRRG3LBn57iSDvG9m3CrN1) supplies the visual design only. Words and terms come from the code: *client* and *daemon*, `EndpointId`; never *source/destination peer* or *node id* for these.
- No superlatives, no exclamation marks, no emoji. A claim carries a number or links to the mechanism.
- The book describes irsync as it is now. Decision records, `docs/superpowers/`, `TODO.md` stay where they are and are not reproduced verbatim; no "written on", "resolved", "remedy N" narrative in the book.
- Moved means: content into book pages, original file deleted, every inbound link in the repository updated. Exceptions: files under `docs/superpowers/` are history and are not edited; `docs/*_DECISIONS.md` get link-only edits (path changes), nothing else.
- Crate READMEs (`crates/{fileset,filegen,stress,netstress}/README.md`) stay, shortened to one paragraph and a link to the book page. `README.md` stays as a pitch, the install line and links to irsync.org and the book.
- In-repo references to a moved document point at its book source path (e.g. `book/src/contributing/bug-hunting.md`), so they work in a clone; the site and READMEs link to `https://irsync.org/book/...`.
- Source and install links: `https://github.com/irsync-dev/irsync`; install line `cargo install --git https://github.com/irsync-dev/irsync irsync` (and `... fileset` for fileset).
- Tokens: `site/tokens.json` is a verbatim copy of the design system's `project/tokens.json`; all colours, type, spacing, radius and shadow come from generated `--ir-*` custom properties. Dark is the primary theme, light the fallback, following `prefers-color-scheme`. Fonts are the system stacks from the tokens; nothing is loaded from a third party.
- One accent per view (`accent` for bytes in flight, the one primary action, links). Text contrast 4.5:1 in both themes.
- Works at 360 px wide: single column, no horizontal page scroll; terminal frames and wide tables scroll inside themselves.
- Build output: `target/site/` (landing at `/`, book at `/book/`). `target/` is already git-ignored; generated `book/theme/tokens.css` is git-ignored.
- Cloudflare Pages projects (created by the author): `irsync-dev` (custom domain `dev.irsync.org`) and `irsync-org` (custom domain `irsync.org`), production branch `main` in both.
- Staging is public and not indexed: `X-Robots-Tag: noindex` on `https://dev.irsync.org/*` and `https://:project.pages.dev/*` via `_headers`. Production is indexed. Promotion uploads staging's exact files; nothing is rebuilt. (Deviation from the spec: there is no staging-only `robots.txt`, because identical files cannot carry a different `robots.txt` per host without server code; the host-scoped header does the job, and a `Disallow` would even stop crawlers from seeing it.)
- Every task ends with these clean: `python3 -m unittest discover -s site/tools -p 'test_*.py'`; `site/build.sh`; `python3 site/tools/check.py --irsync target/debug/irsync target/site` (after `cargo build -p irsync`). Rust code is touched only in comments; when it is, `cargo fmt --all --check` too.

## Review Focus

1. Anchors that rot: the landing page and cross-page links point at headings (`#sessions-and-resume`); rewriting a heading silently breaks them. Fragments are checked, not just files. Pinned in Task 2 (`test_missing_anchor_is_reported`).
2. A dangling reference to a moved document from a script comment, a test comment or a config file (`crates/stress/tools/*.sh`, `docs/telemetry/compose.yaml`, `tools/syscall-sites.py`, `crates/irsync/src/manage/config.rs`). Pinned in Task 2 (`test_reference_to_moved_file_is_reported`).

4. Staging's noindex leaking into production, or production missing from it, since both get the same files. Pinned in Task 8 (`test_noindex_only_for_staging_hosts`).
5. The book's light theme: mdbook's light themes plus the highlight.js colours on the design system's light surface; a dark-only check passes while light code blocks are unreadable. Pinned in Task 1 (`test_light_values_under_light_selector`) and checked by screenshot in Task 2.
