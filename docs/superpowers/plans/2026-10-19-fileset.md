# fileset Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone `fileset` binary with `update` and `check` verbs that records a directory tree's POSIX metadata and BLAKE3 checksums in an in-tree SQLite or fjall manifest and reports differences against it.

**Architecture:** One scan engine (sorted depth-first walker → bounded hashing pool → in-order consumer) driven by two thin verbs. The manifest is a `Store` trait object with SQLite and fjall implementations, keyed by relative path bytes. `update` stamps entries with a generation counter and sweeps the rest; `check` diffs the walk against the store and then does an `lstat` pass over the store for deletions.

**Tech Stack:** Rust 2021 (workspace member), clap 4 derive, blake3, rusqlite (bundled), fjall 3, prost + protox (no system protoc), xattr, crossbeam-channel, indicatif, jiff, anyhow/thiserror, tempfile for tests.

**Spec:** `docs/superpowers/specs/2026-10-19-fileset-design.md`

## Global Constraints

- Crate lives at `crates/fileset/`, binary `fileset`; it must not depend on `irsync` or `irsync-proto`. Workspace dependency table is used for version pinning only.
- Manifest file names: `.fileset.sqlite` (file) and `.fileset.fjall/` (directory). SQLite sidecars `-wal`, `-shm`, `-journal` are never recorded.
- Paths are byte strings everywhere (`Vec<u8>` / `OsStr`), never required to be UTF-8. Root entry key is `.`; children of root have no `./` prefix; components joined by `/`.
- Every stat is `lstat` (`symlink_metadata`). Symlinks are never followed. Xattrs read with the non-deref `xattr::list` / `xattr::get`.
- Directory entries sorted byte-wise before iteration unless `--no-dir-sort`.
- Mount points not crossed unless `--cross-mount-points`; the test is `st_dev != root st_dev`.
- Output lines: `ADD <path> kind=<kind>`, `DEL <path>`, `CHG <path> <field>=<old>→<new> ...`. Warnings `WARN <text>` on stderr. Summary on stderr.
- Exit codes: 0 clean, 1 differences (or warnings with `--fail-on-warnings`), 2 run failed.
- Comparison tiers: relaxed = kind, blake3, target, rdev. Default = relaxed + mode, mtime, size. Paranoid = default + uid, gid, nlink, xattr. `size` and `nlink` never for directories; root `.` mtime exempt; `store`-flagged entries compare kind only.
- `update` reuses a stored hash when kind is file, size, mtime (sec+nsec) and ino match, unless `--rehash`. `check` always hashes.
- Memory must not grow with tree size: no set of visited paths, bounded channels.
- Platforms: Linux and macOS. Tests that need non-UTF-8 file names are `#[cfg(target_os = "linux")]`.

## Review Focus

1. **Root given as a symlink or with a trailing slash**: expected to work on the target directory with `.` as root key. Pinned in Task 7 (`walk_root_symlink_is_followed_once`).
2. **Non-UTF-8 or control bytes in a file name**: expected to round-trip through the store and print escaped (`\xNN`), never panic. Pinned in Task 3 (`escape_non_utf8`) and Task 7 (`walk_non_utf8_name`).
3. **An object changes type between update and check** (file → directory of the same name): expected a single `CHG <path> kind=file→dir`. Pinned in Task 9 (`diff_kind_change_reports_only_kind`).
4. **Interrupted `update` leaving mixed generations**: expected the next `update` to sweep stale entries and `check` to still work. Pinned in Task 10 (`update_sweeps_stale_generation`).
5. **`check` with no manifest at the root**: expected exit 2 with a message naming the two file names looked for, not a panic or an empty "clean". Pinned in Task 6 (`locate_check_without_manifest_errors`) and Task 12 (`cli_check_missing_manifest_exits_2`).

**Interfaces:**
- Produces (in `store/mod.rs`):

```rust
pub const SQLITE_NAME: &str = ".fileset.sqlite";
pub const FJALL_NAME: &str = ".fileset.fjall";
pub const SQLITE_SIDECARS: [&str; 3] = [".fileset.sqlite-wal", ".fileset.sqlite-shm", ".fileset.sqlite-journal"];
pub const SCHEMA_VERSION: u32 = 1;

#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub enum Backend { Sqlite, Fjall }
#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub enum OpenMode { Create, ReadWrite, ReadOnly }
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Meta { pub schema_version: u32, pub generation: u64, pub tool_version: String, pub created_at: i64, pub updated_at: i64 }

pub trait Store: Send {
    fn meta(&self) -> anyhow::Result<Meta>;
    fn get(&self, path: &[u8]) -> anyhow::Result<Option<Entry>>;
    /// Visits every entry in byte-wise key order.
    fn for_each(&self, f: &mut dyn FnMut(&[u8], &Entry) -> anyhow::Result<()>) -> anyhow::Result<()>;
    /// Atomic upsert of all items (xattrs replaced wholesale).
    fn put_batch(&mut self, items: &[(Vec<u8>, Entry)]) -> anyhow::Result<()>;
    /// Deletes every entry whose generation != keep. Returns count deleted.
    fn sweep(&mut self, keep: u64) -> anyhow::Result<u64>;
    fn set_meta(&mut self, meta: &Meta) -> anyhow::Result<()>;
    /// Flush, checkpoint, release. Must be called at the end of a successful update.
    fn close(self: Box<Self>) -> anyhow::Result<()>;
}

pub fn open(path: &Path, backend: Backend, mode: OpenMode) -> anyhow::Result<Box<dyn Store>>;
```

  Errors: `OpenMode::ReadOnly` on `schema_version < SCHEMA_VERSION` → error text contains `run 'fileset update'`; any mode on `schema_version > SCHEMA_VERSION` → error text contains `newer`. `ReadWrite` on an older schema migrates. `Create` on an existing manifest → error.

- SQLite specifics (`store/sqlite.rs`): schema exactly as the spec's Storage section (`meta`, `entries ... WITHOUT ROWID`, index on `generation`, `xattrs ... WITHOUT ROWID`). `pub(crate) fn apply_migrations(conn: &Connection, scripts: &[&str], from: u32) -> Result<u32>` runs `scripts[from..]` in one transaction and returns the new version; `const MIGRATIONS: &[&str] = &[V1_SQL]`. Write modes set `journal_mode=WAL` and `synchronous=NORMAL`. `close` runs `PRAGMA wal_checkpoint(TRUNCATE)` then `PRAGMA journal_mode=DELETE` so the file is self-contained. `ReadOnly` opens with `OpenFlags::SQLITE_OPEN_READ_ONLY`.

```rust

// pipeline.rs
pub enum Decision { Hash, Skip }
pub const WALK_CAPACITY: usize = 1024;
pub const JOB_CAPACITY: usize = 1024;
/// Runs `producer` on its own thread, applies `decide` on the calling thread in walk order,
/// hashes `Decision::Hash` entries on `jobs` threads, and calls `sink` in walk order.
pub fn run<P, D, S>(jobs: usize, producer: P, decide: D, sink: S) -> anyhow::Result<()>
where P: FnOnce(&mut dyn FnMut(WalkEvent) -> anyhow::Result<()>) -> anyhow::Result<()> + Send + 'static,
      D: FnMut(&mut Observed) -> Decision,
      S: FnMut(WalkEvent) -> anyhow::Result<()>;
```

  Hasher behavior: on `Ok(h)` set `entry.blake3 = Some(h)`; on `Err(e)` set `entry.blake3 = None`, insert `Flags::UNREADABLE`, set `hash_error = Some(e.to_string())`. Warnings pass through in order. Only `Kind::File` entries may be given `Decision::Hash`; `decide` is responsible for that.

  Channel layout: producer → `crossbeam_channel::bounded(WALK_CAPACITY)`; main → hashers `bounded(JOB_CAPACITY)`; hashers → main `unbounded` (in flight is bounded by `JOB_CAPACITY + jobs`). Main thread loops with `select!` over the walk and done channels, assigns a sequence number per event, holds completed events in a `BinaryHeap` keyed by sequence, and drains to `sink` while the head equals the next expected sequence. Producer errors propagate out of `run`.
