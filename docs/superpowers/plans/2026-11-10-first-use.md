# First-use pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a newcomer's first visit, install and first sync work on the first try: a home page with ssh and manual setup as two tabs, honest install and alpha wording, a tutorial that leads with the ssh way, a troubleshooting page, and three small CLI messages that catch the wrong-ID mistake and the different-OS dead end.

**Architecture:** CLI changes first (Tasks 1 to 3), because the docs quote their messages. Then the home page (Task 4), README and book introduction (Task 5), the tutorial and the new ssh how-to (Task 6), and the troubleshooting page (Task 7). Task 8 builds and checks everything.

**Tech Stack:** Rust (`crates/irsync`, anyhow, clap), static HTML/CSS in `site/`, mdbook 0.5 in `book/`, Python site checks in `site/tools/`.

**Spec:** `docs/superpowers/specs/2026-11-10-first-use-design.md`. Agreed home page mockup: `docs/superpowers/specs/2026-11-10-first-use/home-mockup.html` (run `site/build.sh` first; it loads styles from `target/site/`).

## Global Constraints

- No JavaScript on the site. The tabs are pure CSS.
- No new site dependencies, no web fonts; colours and sizes come from `tokens.css` variables (`--ir-warn`, `--ir-warn-soft`, etc.).
- Install stays `cargo install --git https://github.com/irsync-dev/irsync irsync`. Release binaries: "Release binaries will be provided once the beta starts."
- Alpha notice, on home page, README and book introduction: irsync is alpha software; the command line and the network protocol may change before the beta; keep another copy of anything you sync with it.
- Example names: client `myclient`, server `myserver`. Example IDs: client `a3e4753e5ea74e64e745e9c4d10b0fd751dbe03049d742eb0ea545c89703dfba`, daemon `4a29f16a4f80a3fd171ef5573c106dbda470ec24f5a97933752746b567ab9aff` (as in the tutorial today).
- No backward compatibility needed for CLI output; update every test and doc that reads the old format.
- Book and site text quote CLI messages exactly as Tasks 1 to 3 define them.
- `python3 site/tools/check.py --irsync target/debug/irsync target/site` must pass: every link resolves and every flag the site names exists.
- Commit messages: short summary line, blank line, short why. No attribution trailers of any kind.

## Review Focus

1. **`id show` piped into scripts.** `irsync id show | tail -1` must still give the bare EndpointId, and the key line must stay copyable on its own line. The labels are separate lines (Task 1 tests this).
2. **Listing with a wrong ID.** `irsync myserver:` is the first remote command in manual setup; it must get the wrong-ID hint too, not only syncs (Task 2 tests both).
3. **Hint shown twice, or for ssh hosts.** The no-address dial error already carries an `id show --daemon` hint; it must not appear twice, and hosts set up over ssh must not get it (Task 2 tests both).
4. **Tabs without a mouse, and on a phone.** Tabs reachable and switchable by keyboard with a visible focus ring; at 360px wide, no horizontal page scroll (terminals scroll inside themselves). Task 4 checks this by hand.
5. **Docs drifting from the real messages.** Every quoted message in the troubleshooting page and tutorial must match the code after Tasks 1 to 3. Task 7 greps for each.

### Task 2: Wrong-ID hint when a hand-added host never answers

A host without ssh setup (alias with no `ssh` key, or a raw EndpointId) that never answers fails today with "gave up after N attempts: …" and no hint, unless the lookup happened to find no address at all. The user who copied the server's client ID saw a plain timeout.

**Files:**
- Modify: `crates/irsync/src/session/reconnect.rs` (new items next to `describe_dial`, around line 212; unit tests in its `mod tests`)

**Interfaces:**
- Produces in `irsync::session::reconnect`:

### Task 7: Troubleshooting page

**Files:**
- Create: `book/src/how-to/troubleshooting.md` ("Troubleshoot a first sync")
- Modify: `book/src/SUMMARY.md` (first item under How-to guides), `book/src/tutorial/first-sync.md` (link already added in Task 6)

Each entry: a heading naming the symptom, the message as a `text` block, the cause, the fix. Entries, in this order:
1. **A host added by hand never answers.** Message: an example `gave up after 5 attempts: …; if you copied this host's ID by hand, …` with Task 2's hint. Cause: the client was given the server's client ID instead of the daemon's (or the daemon isn't running). Fix: `irsync id show --daemon` on the server, then `irsync host add myserver <that id>` on the client.
2. **ssh setup stops: the server runs another OS or CPU.** Message: Task 3's. Fix: install irsync on both machines, follow the tutorial's "Set the server up by hand". Release binaries at beta will remove this step.
3. **The daemon rejected this client's key.** Message: `no_access_hint` in `crates/irsync/src/session/reconnect.rs:190`. Cause: no grant names this client for that path. Fix: `irsync grant add EXPORT <client-id>` on the server. Why `--ssh` and the 15-second check never re-add a removed grant.
4. **A slow transfer that says `relay`.** Where it shows (the live block and the session summary, see `how-to/direct-and-relay.md#see-which-path-a-sync-took`). Cause: hole punching failed. Fix: links to Connections → Relays and Use your own relay.
