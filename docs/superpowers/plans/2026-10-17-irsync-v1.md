# irsync v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build irsync version one: a one-way directory sync tool over iroh with resumable sessions, chunk-level delta transfer, SSH-key identities, and an rsync-compatible command line.

**Architecture:** A Cargo workspace with two crates. `irsync-proto` holds the protobuf-generated wire types plus the pure chunking/hashing code that defines the protocol and has no I/O. `irsync` holds everything else: identity and authorisation, config, index (SQLite), scanner, planner, sender, receiver, session engine, daemon, and CLI. A session (client-side job) survives connection loss and process death; both sides persist plan and progress in their state directories.

**Tech Stack:** Rust stable (1.98), tokio, iroh 1.3, iroh-mainline-address-lookup 0.6, iroh-mdns-address-lookup 0.6, prost 0.14 + prost-build + protox (no `protoc` install), fastcdc 5 (v2020), blake3, ssh-key 0.6 (features `ed25519`, `encryption`, `std`), rusqlite 0.40 (`bundled`), jwalk, nix 0.31, clap 4 (derive), toml, tracing, tempfile (dev).

**Spec:** `docs/superpowers/specs/2026-10-17-irsync-design.md`

## Global Constraints

- Language Rust, stable toolchain; both roles in one executable `irsync`, daemon as subcommand `irsync daemon`.
- Networking via `iroh` 1.x only; ALPN is the exact bytes `irsync/1`.
- Every message on every stream is a proto3 message defined under `proto/irsync/v1/`; those `.proto` files are the normative protocol. Rust types are generated at build time; `protoc` is not required at build or runtime (use `protox`).
- Nothing Rust-specific goes on the wire. Paths on the wire are `bytes`, not `string`.
- Chunking: FastCDC 2020 variant, normalisation level 1, min 65536 / avg 262144 / max 1048576 bytes. Chunk and whole-file hashes are BLAKE3 (32 bytes). These are protocol constants.
- Only Ed25519 keys can be identities. Daemon rejects an unknown `EndpointId` before reading any protocol message.
- Transport: `max_idle_timeout` 60 s, `keep_alive_interval` 5 s, BBR congestion control, connection receive window 64 MiB, per-stream receive window 8 MiB.
- Defaults: `--parallel 32`, `--reconnect 24h`, range-split threshold 64 MiB, dormant session timeout 7 days, `--numeric-ids` on.
- Only a verified file ever appears under its final name. Temp files are `.irsync.<name>.part` in the destination directory (or `--partial-dir`). No deletion of user files without `--delete*`.
- Config: client `~/.config/irsync/config` (ssh_config syntax), daemon `/etc/irsync/irsyncd.toml` or `~/.config/irsync/irsyncd.toml` (TOML), state `~/.local/state/irsync`. `$IRSYNC_CONFIG`, `-F`, `--config` override.
- Platforms: Linux and macOS, x86_64 and aarch64. Code that is platform-specific lives behind `cfg` in `irsync/src/fs/`.
- Logging via `tracing`; `RUST_LOG` honoured.
- Every task: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` pass before commit.
- Test-only hooks (fault injection, counters) live behind a cargo feature `test-hooks` on the `irsync` crate, enabled in `[dev-dependencies]` via `irsync = { path = ".", features = ["test-hooks"] }`; never compiled into release builds.

## Review Focus

Failure modes the spec implies but no happy-path test exercises. Each is pinned to a test in the owning task.

1. **Permission denied on a subtree during the walk** → the sender's listing is marked incomplete and `--delete` must refuse to delete anything unless `--ignore-errors`. (Task 10 `walk_reports_unreadable_dir_as_incomplete`, Task 18 `delete_refused_when_listing_incomplete`.)
2. **Destination runs out of space mid-file** → the error surfaces per file, the `.part` and its range record stay, no final-name file appears, the session continues with other files. (Task 14 `write_error_keeps_partial_and_no_final_file`.)
3. **A path that is not valid UTF-8** must round-trip byte-exactly through listing, planning and the wire. (Task 3 `non_utf8_path_roundtrips`, Task 16 `sync_non_utf8_filename`.)
4. **A symlink inside a module pointing outside the module root** is transferred as a symlink and never followed, in both directions; a client path containing `..` that escapes the module is rejected by the daemon. (Task 9 `module_path_escape_rejected`, Task 16 `symlink_outside_root_not_followed`.)
5. **A source file modified while it is being sent** → whole-file hash mismatch at the receiver; the file is re-planned and re-sent once, never renamed into place corrupt. (Task 16 `file_changed_during_transfer_is_resent`.)

  - Devices/FIFOs (`-D`): receiver `create_special`; requires privilege, otherwise per-file error.
  - Ownership (`-o`/`-g`): applied only when `geteuid() == 0` (else silently skipped like rsync's non-root behaviour); `--numeric-ids` default on; name mapping when off via `nix::unistd::User::from_name` on the receiver.
