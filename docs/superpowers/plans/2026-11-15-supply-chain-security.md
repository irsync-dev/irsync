# Supply Chain Security Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the repo-takeover, dependency and tampered-binary paths into irsync, using GitHub settings, CI checks, release environments, attestations and immutable releases.

**Architecture:** Most of the work is workflow and config changes, guarded by a new Python "policy" test that reads every workflow and fails when a rule is broken: an unpinned Action, a release secret outside the `release` environment, and so on. Logic that would otherwise sit inline in YAML moves into small shell scripts in `.github/scripts/`, tested the way the existing release scripts are. Repo settings are applied and re-checked by one script, `tools/github_settings.py`. Steps only the maintainer can do are marked **MANUAL**.

**Tech Stack:** GitHub Actions, rulesets and environments; dist 0.34.0; cargo-deny; Dependabot; Python 3 `unittest` (with PyYAML and `tomllib`); POSIX sh and bash.

**Spec:** `docs/superpowers/specs/2026-11-14-supply-chain-security-design.md`

## Global Constraints

- Work on branch `supply-chain-security`, one commit per task. Commit messages: a short summary line, a blank line, then a plain-English why. No attribution trailers of any kind.
- `release.yml` is generated by dist 0.34.0. Never hand-edit it. Change `dist-workspace.toml`, run `dist generate`, and commit both. `dist generate --check` must pass.
- Every `uses:` of a third-party Action is a 40-character commit SHA followed by a version comment, for example `uses: actions/checkout@<sha> # v6.0.1`. Local `./.github/workflows/...` calls are exempt.
- No rule may need a second person. 0 required approvals, and self-review is allowed on the `release` environment.
- The release path stays working: `release-gate.yml` → `release.yml` → `packages.yml` and `release-notes.yml`, plus `release-resume.yml`, including dry runs.
- Per-task checks, run after every task:
  - `python3 -m unittest discover -s .github/scripts/tests`
  - `python3 -m unittest discover -s site/tools -p 'test_install.py'`
  - `actionlint -shellcheck= -pyflakes=`
  - `dist generate --check`
- Before pushing (Task 8), run the full regression in `AGENTS.md`.
- Deny settings from the spec: advisories, unmaintained and yanked crates **fail**. Exceptions go in `deny.toml` `ignore` with the ID and a reason. Allowed sources are crates.io and `https://github.com/irsync-dev/iroh` only. Duplicate versions **warn**.
- Dependabot: `cargo` and `github-actions`, weekly, one grouped PR per ecosystem, cooldown 7 days. Security updates are not delayed.

## Review Focus

1. **Dependabot bumps a pinned Action.** Its PR rewrites `@<sha> # v6.0.1` to a new SHA and a new comment. The policy test must accept that form, so Dependabot PRs aren't red. Covered by Task 1, `test_pin_format_accepts_dependabot_style`.
2. **A Markdown-only PR under the `main` ruleset.** The required `CI result` check must still report success, or the PR can never merge. Covered by Task 2, `test_docs_only_change_is_not_code`.
3. **A heavy CI job is cancelled or fails.** `CI result` must fail, not count it as skipped. Covered by Task 2, `test_cancelled_need_fails`.
4. **Resume started on `main` out of habit.** It must stop with a message naming the exact command to run instead. Covered by Task 5, `test_resume_refuses_branch_ref`.
5. **A pre-release tag.** Our own Homebrew job must not push a formula to the tap, as dist's job didn't. Covered by Task 5, `test_homebrew_job_skips_prereleases`.

### Task 6: Settings as code

**Files:**
- Create: `tools/github_settings.py`
- Create: `tools/tests/test_github_settings.py`

**Interfaces:**
- `desired(maintainer_id: int) -> dict[str, RepoSettings]`: the target state per repo. `RepoSettings` is a `dict` with these keys, each optional per repo: `security`, `actions`, `immutable_releases`, `environments`, `rulesets`.
- `diff(want: dict, have: dict) -> list[str]`: one line per difference, `"<repo>: <path>: want X, have Y"`. Keys in `have` but not in `want` are ignored. Rulesets are matched by `name`.
- `fetch(repo: str) -> dict`: reads the live state with `gh api`.
- `apply(repo: str, want: dict) -> None`: writes it.
- CLI: `tools/github_settings.py check` (the default; prints the diff, exits 1 if not empty) and `tools/github_settings.py apply [--repo R]`.
- `check` also reports the org's `two_factor_requirement_enabled`. There's no API to set it, so `apply` only prints a reminder.

Desired state:

| Repo | Settings |
|---|---|
| `irsync-dev/irsync` | Secret scanning on; push protection on; Dependabot security updates on. Actions: `enabled: true`, `allowed_actions: all`, `sha_pinning_required: true`. Immutable releases on. Environment `release`: custom deployment policy, one tag rule `v*`, reviewer = `maintainer_id`, `prevent_self_review: false`. Environment `site`: custom policy, branch `main`, no reviewers. Ruleset `main` (branch, `~DEFAULT_BRANCH`): `deletion`, `non_fast_forward`, `pull_request` with 0 approvals, `required_status_checks` with context `CI result`; `bypass_actors: []`. Ruleset `Release tags` (tag, `refs/tags/v*`): `update`, `deletion`, `non_fast_forward`; no `creation`; `bypass_actors: []`. |
| `irsync-dev/iroh` | Secret scanning and push protection on. Ruleset `Pinned branches` (branch, `refs/heads/irsync-*`): `deletion`, `non_fast_forward`; no bypass. |
| `irsync-dev/homebrew-tap`, `irsync-dev/packages` | Secret scanning and push protection on. Ruleset `Default branch` (`~DEFAULT_BRANCH`): `deletion`, `non_fast_forward`; no bypass. No PR rule: the release jobs push directly. |
