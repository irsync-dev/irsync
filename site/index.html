irsync — resilient file synchronization

irsync is a one-way directory synchroniser in the mould of rsync, rebuilt for today's networks. It takes rsync's flags and its trailing-slash rule.

It connects through iroh, so it gets through NATs and firewalls without port forwarding or dynamic DNS. A transfer outlives the network connection: after a drop, a closed laptop or Ctrl-C, the same command carries on where it stopped.

Correctness comes first: a completed sync leaves an exact copy, and you can check that yourself with fileset.

  • Linux or macOS on both ends
  • Rust, to build it
  • ssh access to the server (optional)

What irsync does

  • Transparent Connections

    The daemon is reached by its EndpointId, the public half of its key, not by an address. The client pins that key for each host; there is no trust-on-first-use.

    Identity and trust →

  • Resilient Transfers

    A session outlives any connection. After a drop the client redials for up to 24 hours by default; after Ctrl-C or a reboot, the next run of the same command resumes from the last verified chunk.

    Sessions and resume →

  • Efficient Bandwidth Usage

    A session keeps up to 4,096 files between request and acknowledgement, which hides the per-file round trips, and up to 32 QUIC data streams by default fill the link; a large file spreads over several streams.

fileset: check any copy, made by any tool

fileset records the checksums and metadata of a directory tree. Check a copy against that record after rsync, rclone, cp or irsync, or months later to catch bitrot. 

$ fileset init ~/Photos
$ rsync -a ~/Photos/ /mnt/backup/Photos/
$ fileset check /mnt/backup/Photos

If you know rsync

-a and rsync's trailing-slash rule work as they do in rsync; -v lists files as rsync's does, but -vv and -vvv turn on debug and trace logs. --delete deletes after the transfer, as --delete-after does. What changes is underneath.

Dimension rsync irsync
Transport TCP or SSH iroh QUIC, NAT traversal, pinned Ed25519 identities
Delta unit basis block, 700 B .. 128 KiB, ~sqrt(size) content-defined chunk, 64 KiB .. 1 MiB, 256 KiB average; blocks of 512 B .. 4 KiB inside a missing chunk
1-byte edit in a 1 GiB file ~32 KiB literal + tokens ~1 KiB literal + a few operations, with ~10 KiB of block signatures the other way
Rename detection none (name similarity only, --fuzzy) by content: a renamed or copied file's chunks are found in the index and copied locally
Digest caching across runs none; -c re-reads everything persistent SQLite index keyed on size, mtime, ctime, inode
Streams one, in order up to --parallel QUIC streams (32 by default), runs split at 64 MiB
Files in flight pipelined, bounded by the window up to 4,096 per session, from request to acknowledgement
Resume --partial keeps bytes; the next run re-checksums them chunk-granular, verified ranges persisted; plan persisted
Round trips before first data byte ~0 (pipelined) 1.5 (plan, chunk list, request)
Compression -z none

Install

irsync builds from source with Rust's cargo. If you have no Rust yet, get it from rustup.rs first. The build takes a few minutes. 

$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh   # only if you have no Rust
$ cargo install --git https://github.com/irsync-dev/irsync irsync

Release binaries will be provided once the beta starts.

Linux and macOS, x86_64 and aarch64, as client and as daemon. With ssh, the client is enough: the first sync copies irsync to the server when both run the same OS and CPU. When they differ, install irsync on both machines and use the setup under “Without ssh”.

fileset is a separate tool that works with any copy tool, not only irsync. It records the checksums and metadata of a directory tree and later checks the tree against them. 

$ cargo install --git https://github.com/irsync-dev/irsync fileset
