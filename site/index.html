rsync, rebuilt for today's networks

irsync is a one-way directory synchroniser. It runs on both ends of a transfer and connects through iroh, so two machines find each other and traverse NATs and firewalls without port forwarding, dynamic DNS or SSH tunnels.

What irsync does

  • No port forwarding

    The daemon is reached by its EndpointId, the public half of its key, not by an address. The client pins that key for each host; there is no trust-on-first-use.

    Connections →

  • Survives a bad link

    A session outlives any connection. After a drop the client redials for up to 24 hours by default; after Ctrl-C or a reboot, the next run of the same command resumes from the last verified chunk.

    Sessions and resume →

  • Fills the link

    Up to 4,096 files in flight per session over 32 QUIC data streams by default, a scan that runs alongside the transfer, and a persistent index that makes repeat runs over a mostly unchanged tree cheap.

Install

$ cargo install --git https://github.com/irsync-dev/irsync irsync

Linux and macOS, x86_64 and aarch64, as client and as daemon. Install it on both machines.

Optional: fileset, an independent tool that records the checksums and metadata of a directory tree and later verifies the tree against them, for example after a transfer (Verify a transfer with fileset).

$ cargo install --git https://github.com/irsync-dev/irsync fileset
