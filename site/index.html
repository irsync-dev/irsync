Sync files between any two machines, over any network

Copy files and directory trees the way rsync does, directly between your devices, without configuring firewalls, port forwarding or static IPs.

  • No open ports. The two machines find each other through NATs and firewalls, and use a relay only when there is no direct path.
  • Picks up where it stopped. Transfers survive a switch of network. If the connection drops, run the same command again; it resumes at the exact byte.
  • Encrypted end to end. Each side talks only to the keys it was given.

Your first sync Read the introduction 

# Install (Linux and macOS)
$ curl --proto '=https' --tlsv1.2 -LsSf https://irsync.org/install.sh | sh -s -- --beta
# Copy a directory to a server you can ssh into
$ irsync -av ~/Photos/ myserver:/srv/photos/

Beta. Both ends run irsync; it is not a drop-in replacement for rsync. The command line and the protocol may still change, so keep another copy of anything you sync with it. Known limitations.

Get started

  1. 1

    Install

    $ curl --proto '=https' --tlsv1.2 -LsSf https://irsync.org/install.sh | sh -s -- --beta

    Linux and macOS. Installs irsync and fileset into ~/.local/bin. There is no stable release yet, so --beta takes the newest beta release. There are also other ways to install.

  2. 2

    Sync

    $ irsync -av ~/Photos/ myserver:/srv/photos/

    If ssh myserver logs you in, the first run sets the server up too. Later runs connect over iroh and do not use ssh. No ssh? Set the server up by hand.

  3. 3

    Interrupted? Run it again

    If the connection drops or you stop the transfer, run the same command again. It resumes where the last run stopped.

How it connects

irsync connects through iroh, an open-source networking library. You do not need to set anything up for it.

Directly, when it can

The two machines find each other and connect directly, even when both sit behind a home router or a firewall. The server is found by its key, not by an IP address.

Encrypted, key to key

Traffic is encrypted end to end. The client only connects to the server key it was given, and the server only lets in keys it has granted. More in Identity and trust.

Through a relay, when it must

When no direct connection is possible, the encrypted traffic passes through a relay server, which cannot read it. By default that is a public relay run by n0, the developers of iroh. Run your own, or refuse relays with --no-relay. More in Direct or relay.

Before you rely on it

  • The command line and the protocol may change before the first stable release. Keep another copy of anything you sync with it.
  • It is not a drop-in replacement for rsync. It has its own protocol, so both ends must run irsync.
  • Some rsync options are missing, such as -X, -A and -z. Extended attributes and ACLs are not copied.
  • Windows and NTFS is not supported. Relayed connections are much slower than direct ones.

The full list is in Known limitations.

Help

Ask questions and report bugs in GitHub Issues. If a first sync fails, see Troubleshooting. Report security problems privately to security@irsync.org.

A helper that checks that a copy is exact, whichever tool made it: rsync, rclone, cp or irsync. Start with the introduction to fileset.
